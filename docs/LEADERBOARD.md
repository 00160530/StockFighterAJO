# 排行榜規劃與平台比較

查核日期：2026-10-17。0.4 版只有本機輪次榜預覽，尚未建立雲端專案、線上帳號或跨玩家榜單，也不會把存檔上傳。首頁「排行榜」與遊戲選單均可開啟預覽。

## v0.6 模式分榜

排行榜有「人生模式／自由模式」兩個切換按鈕，與超額報酬、最大獲利、翻車紀錄三種分類獨立切換。人生採 tw-life-v1，自由採 tw-v1，同時匹配資料截止日。檢視另一模式不代表解鎖遊玩權限。

## 玩家看到的數據

主榜：名次、玩家暱稱、超額報酬（百分點）、最終總資產、最大回撤、實際成交次數。展開個人成績後，顯示最大獲利及最大虧損那筆交易的標的、日期、股數、成交價與淨損益。暱稱待雲端身分方式選定後實作；本機預覽使用輪次識別碼，沒有虛構玩家。

獨立趣味榜：單筆最大獲利依淨收益金額由高至低；單筆最大虧損依淨虧損金額由大至小。交易次數是參考數據，不以頻繁交易作為主榜獎勵。

主榜僅比較跑完同一段完整歷史並已結算的輪次，不收進行中、重開、資料未齊或中途破產。按超額報酬排序，同分依較低最大回撤、較少成交、較早提交時間排序。線上正式版每位玩家在同一規則／資料版本只保留一筆最佳成績，避免同一人占滿榜單。本機輪次預覽可列同一瀏覽器的多輪成績。

## 高光定義

- 一筆賣出成交是一筆高光，分批賣出分開比較；未實現損益與股利不列入該筆。
- 移動加權平均成本含買入手續費；分攤成本採與引擎相同的分角精度，賣出淨收益再扣除賣出手續費與交易稅。
- 0050 分割時增加股數、不增加成本，避免舊存檔重算錯誤。
- 同金額保留先發生的一筆；沒有正收益賣出就顯示尚無獲利，沒有負收益賣出就顯示尚無虧損。
- 交易次數只算成交：買一次再賣一次為 2 筆。送單、取消、拒單、股利、分割不增加次數。
- 舊遊戲存檔有完整 log 時可重建；只有舊版結局摘要且已無交易明細時，保留原摘要並標示缺少明細，不填假數據。

## 平台比較

| 方案 | 官方免費額度重點 | 對這個遊戲的取捨 |
| --- | --- | --- |
| Supabase | 每專案 500 MB 資料庫、5 萬 MAU、每月 50 萬 Edge Function 呼叫；免費專案閒置一週會暫停 | 優先建議。PostgreSQL、登入及資料管理整合，適合排序、查單筆交易與日後管理異常成績。需接受免費版閒置暫停限制。 |
| Cloudflare Workers + D1 | D1 共 5 GB、每日 500 萬列讀取與 10 萬列寫入；Workers 免費每日 10 萬請求 | 只做輕量榜單 API 時很合適。需多寫登入、API 與管理介面；讀取列數按掃描量計算，須有索引。 |
| Firebase Firestore Standard | 1 GiB、每日 5 萬文件讀取與 2 萬文件寫入 | 可用且有完整產品，但這個榜單同時要比多欄位、查高光明細，以 SQL 較容易管理，是本專案的實作判斷。 |

官方來源：[Supabase Pricing](https://supabase.com/pricing)、[Supabase Billing](https://supabase.com/docs/guides/platform/billing-on-supabase)、[D1 Pricing](https://developers.cloudflare.com/d1/platform/pricing/)、[Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/)、[Firestore Pricing](https://firebase.google.com/docs/firestore/pricing)。額度各自採不同計量單位，不能把「列」與「文件」或「請求」當成同一種流量。

若優先考慮管理方便，用 Supabase；若主要目標是單純的榜單 API、願意多做登入及管理功能，再選 Workers + D1。Workers 免費方案每次執行另有 10 ms CPU 額度，完整遊戲重播須實測、最佳化或拆段處理，不能只看資料庫空間就假設免費方案足夠。這是依本遊戲需求的建議，不代表某平台普遍優於另一個。

## 接雲端時的結構

GitHub Pages 繼續放遊戲和行情；本機自動／手動存檔維持原樣。玩家在結算後自願提交暱稱與遊玩操作，服務端以指定資料版本和同一份引擎重播，計算資產、超額報酬、回撤與高光後才寫入榜單。不能只信任前端傳來的總資產或摘要。

預定資料：

- players：經登入系統識別的 player_id、暱稱。是否訪客或 Google 登入待確認；訪客若清除瀏覽器資料可能無法找回身分。
- runs：run_id、player_id、ruleset_id、dataset_id、server_verified、結算日期、資產、基準資產、alpha、回撤、成交次數、費稅、驗證後的兩筆高光、服務端提交時間。
- 操作證據：送單／全部模式／取消／劇情選擇與遊戲日期，足供同一引擎重播。不要只收本機填好的 fill、history 或終值。

防止重複提交採 player_id + run_id 冪等鍵，並限制提交頻率；正式榜查詢僅公開已驗證的成績及必要欄位。Supabase 資料表啟用 RLS，禁止瀏覽器直接寫入認證成績，寫入只由驗證函式執行。公開網頁只能放公開用的 publishable key；service_role／secret key 留在服務端環境。

伺服器重播能攔下改資產、捏造成交等數值作弊，不能證明離線遊玩從未讀檔重試。若日後有認真競賽或獎勵，另設服務端持有進度、禁止回退的競賽模式；目前單機模式保留讀檔自由，不宣稱已具競賽級防作弊。

RLS 及身分參考：[Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)、[Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous)。排行榜每次只讀前 20 名並短暫快取，不必每日行情推進就寫雲端，也不必開 Realtime。

資料版本必須使用行情內容雜湊，而非只有截止日期；現有本機預覽以 tw-v1 + datasetEnd 隔離已知版本。接正式線上榜前補上完整 dataset_id 與驗證流程，不能直接把本機預覽改名成全球榜。
