# 玩家設定與自動排行榜（0.16.31 起）

0.16.34 的榜單摘要、完成計數、後台全量查詢及發布順序另見 [排行榜與後台查詢摘要](TOP100_AND_ADMIN_SNAPSHOTS.md)。

本專案使用 AI 輔助開發，包含程式、劇情及美術素材。

## 玩家資料

既有匿名 ID 與 Token 繼續使用，不以暱稱登入或重新產生身分。`sf_players.nickname` 是排行榜及管理成績查詢的唯一暱稱來源；`avatar_id`、`avatar_character` 是排行榜頭像來源。開始新遊戲先讀取雲端，尚無暱稱時必須設定；設定成功即固定，沿用 2–20 字、NFC、字元及不重複規則。歷史重名身分維持既有相容政策。

`GET /v1/profile` 回傳 nickname、avatarId、avatarCharacter；`POST /v1/profile` 支援首次設定及只更新頭像。Token 驗證、唯一性觸發器及限流仍有效。重新開啟遊戲先使用既有 Token 同步；失敗保留本機快取，並標示尚未同步，不假設雲端已設定暱稱。遊戲存檔、遊戲角色及本機歷史不從雲端覆蓋。

`sf_stock_quotes` 與留言版本表的頭像仍是該次留言的快照。改排行榜頭像只寫 sf_players，不更新金句或遊戲所選角色。

## 提交及重試

最終結算自動提交 won、lost；經既有完成條件確認的破產也自動存為失敗成績，另以 finish_status=bankrupt 保留原結局，不改動負資產。正常完整輪次沿用原日期、基準、最低時長、分數、交易、高光及融資檢核；破產沿用原完成驗證，追加既有交易摘要檢核。不新增可上傳的「中途放棄」狀態。

新前端不傳送 nickname、avatarId、avatarCharacter。為已開啟的舊網頁保留過渡解析：若玩家從未設定，舊提交可首次寫入玩家資料；已有暱稱不可變更，已有頭像不被成績提交覆寫。這些欄位不寫入 sf_runs。

先在本機保留綁定匿名 ID、Session、到期日的 pendingScores，送出成功才轉為 receipt。回應遺失可用同一請求重試，SESSION_USED 帶回伺服器回條；原子 Session 消耗與 session_id 唯一限制不變。名次查詢暫時失敗也不會重建成績。使用者可重試或放棄自動重試；結算內容、儲存與匯出不等待 API。重新開啟及恢復連線補送未放棄的待送成績，不自動補傳過去從未要求上傳的歷史輪次。

完成計次繼續使用 sf_life_completions，與成績表各自依 session_id 去重。原完成時間及舊時長空值不會被重送覆寫。

## 榜單、自己與通知

每個模式各有四榜，每榜前 100 名：

| 分類 | 指標 | 條件 |
| --- | --- | --- |
| won（超額報酬） | 最終總資產 | 只限贏過大盤；沿用原同分排序 |
| financing（融資） | margin_summary.totalBorrowedCents | 累計實際借款，大於零；不限勝負 |
| gain（單筆獲利） | gain_cents | 最高單筆已實現淨利，大於零；不限勝負 |
| reincarnation（輪迴次數） | 有效完成紀錄 COUNT | 按 sf_sessions.mode 分開計次，大於零 |

前三榜每人保留最高一輪，排名採固定次序以穩定處理同分；輪迴榜同次數依較早達成時間及匿名 ID 排序。隱藏成績不參與前三榜，但不扣除原有效完成次數；被停用的匿名身分不公開列榜。雲端失敗紀錄與原 sf_best_scores 留存供管理查詢，公開 lost 及舊 metric=loss 端點不再提供；本機翻車紀錄不變。

`GET /v1/boards` 可回傳兩模式四分類及前百名內的本人名次，前端共用五分鐘快取；換頁籤不重抓，成績／頭像更新及身分變更使快取失效。公開列只帶 isOwn，不帶 player_id 或 Token。0.16.34 起從每榜最多 100 筆的摘要讀取，榜外 entry 為 null，顯示鼓勵文字，不查詢完整榜外名次，也不標記其他玩家。

通知由伺服器比較本輪之前的最佳紀錄及實際排名；首次進前 100 名通知上榜，指標提高或同分排序產生更佳成績時通知刷新，既有最佳未變不重複恭喜。回條持久化通知種類與數值，不重複存暱稱或頭像；恢復回條時重新核對目前名次，已跌出百名或不再是本輪最佳的項目不通知。前端記錄已顯示狀態，不自行計算名次。

## Migration、發布及回復

- `0024_player_profile.sql`：新增玩家頭像，以最新一筆未註銷成績（時間相同以 ID 排序）的頭像遷移；無資料使用小韭微笑。先移除舊暱稱索引，再移除成績的三個顯示欄位。歷史 Migration 不改寫。
- `0025_finished_scores.sql`：使用 defer_foreign_keys 與暫存副本重建成績表，保留所有原值、ID、原始列順序與外鍵關係，允許已驗證破產的負資產，新增 finish_status 和 upload_receipt；重建相關索引。不刪除玩家、成績、完成紀錄、金句或管理資料。
- 正式發布前必須取得完整 D1 匯出及當前 Worker 版本，核對帳號／資料庫與待執行 Migration。先在本機含外鍵及既有成績的樣本執行兩個 Migration，對照舊資料及 foreign_key_check。發布前也以正式 D1 完整匯出在本機驗證遷移及外鍵；備份僅保留在私人工作目錄，不加入 Git。
- 舊 Worker 不能在移除 sf_runs 欄位後繼續服務，新 Worker 也不能先套用舊 schema。正式上線時需在短暫 API 維護窗口套用兩個 Migration 並部署對應 Worker，驗證原資料與 API 後才發布新 Pages；窗口內前端保留結算與待送重試。不要單獨先推送本機分支至正式 Pages。
- schema contraction 後不能只切回舊 Worker。需要回復時先保留維護窗口後新增的資料，再由發布前 D1 匯出在隔離資料庫驗證還原及舊 Worker，重新合併窗口後資料並核對資料筆數／外鍵；不能直接以舊備份覆蓋新增玩家成績。也可優先修復前進，保持新 schema 與舊身分不變。

本機驗收使用 `work/leaderboard-preview.mjs` 的獨立資料庫與示範股友；不讀寫正式環境。`/review/` 提供結算示範，只有這個本機網站的測試身分和自動進度會被替換。

## 顯示與後台查詢

首次設定與排行榜更換頭像共用同一個角色分頁、五欄心情選擇面板，排行榜按鈕顯示目前頭像與角色／心情名稱。結算僅保留上方「重試上傳」，底部為匯出對帳單及保存進度。

四種榜單共用固定 48px 名次欄。點暱稱以獨立對話框顯示成績，不替換、關閉或重繪原排行榜，關閉後保留原頁籤與捲動位置。

管理後台 players API 額外回傳 sf_players.avatar_id、avatar_character，包含未上傳玩家及預設頭像；不回傳 Token。成績排列 financing_total 依 margin_summary.totalBorrowedCents 由高至低，打平依上傳時間及成績編號由新至舊，無值視為零。不需要額外 Migration。

暱稱設定視窗的底部操作列固定顯示；暱稱與頭像內容可獨立捲動，儲存狀態與錯誤留在按鈕列。
