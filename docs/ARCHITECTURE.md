## 逐日流程

1. 盤後輸入的委託排入 `orders`。
2. 按前進，日期增加一個交易日。
3. 開盤前先辦理當日分割、除息權利登記；依此前持股建立應收股利。
4. 到期股利支付到現金；遇假日延至下一個模擬交易日。
5. 基準以發放後的首個有效開盤價再投入。
6. 玩家排隊委託按該日原始開盤價成交；暫停交易、股數不足、現金不足則整筆取消。
7. 以收盤估值記錄玩家與基準績效，檢查破產或終點。
8. 觸發日期事件，儲存到 localStorage，重新渲染畫面。

配息權利取自除息日前持股，不會讓除息日當天才買入的股票領到本次股利。分割增加股數，持股總成本不變。

## 行情欄位

`instruments[id].rows` 每列依序為：

```text
[交易日期 YYYY-MM-DD, 開, 高, 低, 收, 成交股數, 成交金額元]
```

`chips[date]` 內含 `foreign`、`trust`、`dealer` 的買減賣。外資含外資自營商，自營商合併自行與避險；大盤的彙總 total 列不重複加總。大盤 `chipUnit` 是元，其餘為股。

`dividends` 為 `{ex, pay, amount}`。金額是除息前每股現金。`splits` 為 `{date, ratio}`。0050 分割資料以證交所公告核對後固定列入；不以價格跳空猜測公司行動。

一般交易日由加權指數日曆決定，其他個股不得默默缺日。0050 分割停止交易日是明確允許的例外，無法成交時沿用最近收盤估值。

## 防止介面提前揭露

- `visibleRows()` 只回傳當下日期以前的行情，均線亦只由這些資料計算。
- `chipCutoff()` 固定為前一交易日；Canvas 不畫當日法人，提示也不顯示。
- 分割還原僅套用截至遊戲當下已生效的分割，不使用完整歷史事後還原價。
- 原型事件不提供當時尚未發生的實際價格或買賣訊號。

所有靜態資料仍能被查看原始碼的玩家讀取，這是離線架構的性質。現有控制是遊戲內時間線，不是防作弊安全邊界。

## 儲存

自動存檔 key 是 `taigu-warrior.v1.auto`；三個手動欄位為 `.slot1`—`.slot3`。存檔含版本、資料終點、日期索引、現金、持股與成本、應收股利、基準帳戶、委託、紀錄、事件與心理壓力、每日績效。

JSON 匯入限制 8 MB，驗證格式、資料範圍與帳戶欄位後才替換進度。所有來自匯入的顯示字串經跳脫。CSV 包含 UTF-8 BOM、欄位引號與公式字首處理。存檔無加密、簽章或跨裝置同步。

目前版本只以資料終點檢查版本相容；若日後更正既有日期或價格，應提升版本並設計遷移器，不能假設相同終點代表完全相同資料。
